Auto-Update — como assinar e distribuir

Para baixar e instalar automaticamente, precisamos de uma estratégia de assinatura. Qual abordagem prefere?

A

tauri-plugin-updater (oficial + assinado)

Usa o plugin oficial do Tauri. O app verifica um endpoint JSON com a versão mais recente, baixa o instalador, valida a assinatura criptográfica, e lança o updater silenciosamente.

Esforço alto
O que é necessário:
  • Gerar keypair (tauri signer generate)
  • Adicionar chave privada como secret no GitHub Actions
  • CI assina os artifacts em cada release
  • Hospedar latest.json (pode ser o próprio GitHub Releases)
✅ Mais seguro — instaladores verificados criptograficamente
✅ Experiência 1-clique
⚠ Setup inicial mais complexo
B

Download + lançar instalador (sem signing)

O app já detecta a nova versão via GitHub API (código existente). Adicionamos: download do instalador para temp dir e execução via Command::new() ou shell.

Esforço médio
Fluxo:
  • Clique em "Atualizar" no ChangelogModal
  • Baixa o .msi / .deb / .AppImage correto para o SO
  • Lança o instalador (Windows: msiexec /i, Linux: abre o arquivo)
  • App pode fechar após lançar
✅ Aproveita a infra de releases já existente
✅ Sem keypair nem mudanças no CI
⚠ Sem verificação criptográfica (mas é GitHub HTTPS)
C

Download + verificar SHA256 + lançar

Igual ao B, mas antes de lançar o instalador, verifica o SHA256 do arquivo baixado contra um hash publicado no release (arquivo .sha256 no GitHub Releases).

Esforço médio
Extra em relação ao B:
  • CI gera sha256sum de cada artifact e sobe como asset
  • App baixa o .sha256, compara com o hash local
  • Rejeita se não bater — avisa o usuário
✅ Proteção razoável contra download corrompido
✅ Sem keypair
⚠ Não protege contra repositório GitHub comprometido
