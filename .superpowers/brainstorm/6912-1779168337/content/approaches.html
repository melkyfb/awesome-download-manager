Abordagem para a V2 — Qual stack de componentes?

Todas mantêm a mesma base: React + Tauri + Redux + i18n + sistema de temas. A diferença está na biblioteca de componentes.

A

shadcn/ui + Tailwind Recomendado

Componentes headless (Radix UI por baixo). Traz dialogs, bottom sheets, cards, sliders, progress bars — tudo acessível e sem opiniões visuais fortes. Nosso sistema de temas (CSS variables) encaixa perfeitamente.

Prós

  • Sistema de temas existente funciona sem adaptação
  • Componentes modernos e acessíveis (Radix)
  • Leve — só inclui o que usar
  • Visual totalmente controlável via Tailwind
  • Padrão da indústria em 2025

Contras

  • Requer copiar componentes no repo (by design)
  • Menos "Material" por padrão — mas é configurável
B

Material UI (MUI v6)

A biblioteca Material Design 3 mais completa para React. Botões, cards, bottom navigation, FAB, dialogs — tudo seguindo as diretrizes do Android Material You.

Prós

  • Android/Material feel nativo out-of-the-box
  • Componentes ricos e bem testados
  • Suporte a temas via MUI theme engine

Contras

  • Pesado (~300KB gzip)
  • Sistema de temas MUI conflita com nossas CSS variables
  • Precisa migrar os 35+ temas para o formato MUI
  • Opinionated — mais difícil de customizar
C

Tailwind puro + componentes custom

Redesenhar tudo do zero com Tailwind. Máximo controle, sem dependências novas. Mesma abordagem atual, mas com design V2.

Prós

  • Controle total sobre cada pixel
  • Zero dependências adicionais
  • Continuidade com o que já existe

Contras

  • Reimplementar acessibilidade (foco, ARIA, teclado)
  • Bottom sheets, modals, etc. do zero
  • Mais trabalho para alcançar qualidade equivalente
